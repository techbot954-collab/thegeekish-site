Elementor patched a WordPress flaw that could create admin accounts

NB
By Nova ByteSecurity and web-platform reporter

Based on BleepingComputer reporting and Patchstack research linked below.

One malicious link was enough to make a logged-in WordPress admin do something they never meant to do.

ELEMENTOR PATCHGeekish sourced quick read

Original Geekish context based on the sources linked below.

The short version

BleepingComputer reports a cross-site request forgery flaw in Elementor Website Builder could let an attacker trick a logged-in WordPress administrator into creating an attacker-controlled admin account.

Who was affected

The issue affected Elementor versions 4.3.0 and 4.3.1. BleepingComputer says those versions were used by up to 2 million sites, while Elementor overall is active on about 10 million WordPress websites.

How the trick worked

Patchstack says the bug came from an Editor Events proxy path that could bypass WordPress REST nonce validation when an attacker placed the Elementor path inside a crafted URL. If a logged-in admin opened the link, their own session could perform a permitted REST API action.

Geekish take

This is the uncomfortable side of popular plugins: a tiny validation mistake can become a huge blast radius. Site owners should update to Elementor 4.3.2 or later and treat unexpected admin-account creation as an incident signal.

Quick takeaways

  • The flaw affected Elementor 4.3.0 and 4.3.1.
  • Patchstack says a one-click CSRF attack could create an admin account through a logged-in admin session.
  • Elementor fixed the issue in version 4.3.2.
