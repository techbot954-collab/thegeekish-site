F5 patches a BIG-IP APM zero-day already under attack

NB
By Nova ByteAI, chips, and infrastructure reporter

Based on BleepingComputer's report, F5's advisory, and CISA's KEV alert.

This is the kind of enterprise edge-device bug security teams hate: remote code execution risk, exposed appliances, and confirmed exploitation.

Original Geekish context based on the sources linked below.

The short version

BleepingComputer reports that F5 released security updates for CVE-2026-94127, a critical BIG-IP APM vulnerability that has already been exploited. The flaw affects instances configured as an OAuth Authorization Server when an APM access policy and OAuth profile are configured on a virtual server.

Why defenders care

CISA added the F5 bug to its Known Exploited Vulnerabilities catalog on September 22, alongside three other exploited vulnerabilities. CISA says KEV-listed flaws are frequent attack vectors and urges organizations to prioritize risk-based remediation.

What admins should check

F5 says deployments using APM strictly as an OAuth Client or Resource Server without OAuth authorization server profiles are not affected, according to BleepingComputer's summary of the advisory. Organizations that cannot immediately patch should review F5's mitigation guidance and look for indicators of compromise.

Geekish take

Edge access systems sit close to identity, traffic, and internal apps, so "just another appliance patch" can turn into a breach window fast. If BIG-IP APM is in the stack, this deserves urgent inventory, patching, and log review.

Quick takeaways

  • F5 patched CVE-2026-94127 after reports of active exploitation.
  • The affected scenario involves BIG-IP APM OAuth Authorization Server configurations.
  • CISA added the flaw to its Known Exploited Vulnerabilities catalog.
