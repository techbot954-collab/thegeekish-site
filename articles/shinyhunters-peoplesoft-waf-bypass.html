ShinyHunters found a WAF bypass in PeopleSoft attacks

A mitigation is only as good as the paths attackers cannot route around. This Oracle PeopleSoft campaign now has a bypass wrinkle.

Original Geekish context based on the sources linked below.

The short version

BleepingComputer reports the ShinyHunters extortion gang is using a URL-encoding trick to bypass web application firewall rules deployed against Oracle PeopleSoft CVE-2026-35273 attacks.

What changed

The important part is the bypass. Defenders may have added WAF rules to block known exploit traffic, but the report says attackers found an encoding variation that lets exploitation resume on vulnerable servers.

What admins should hear

WAF rules can buy time, but they are not a replacement for patching and exposure reduction. If a campaign can mutate request formatting, teams need to verify whether the actual PeopleSoft instance is fixed, monitored, and reachable only where necessary.

Geekish take

This is why security teams get twitchy about temporary mitigations. Attackers do not need a new vulnerability if they can make the old one look different enough to pass through the front door.

Quick takeaways

  • ShinyHunters is reportedly bypassing WAF rules for a PeopleSoft flaw.
  • The trick involves URL encoding that changes how exploit traffic is seen.
  • Patching and exposure checks matter more than relying on edge rules alone.
